Cedar's agent platform combines persistent instructions, connected data, user tasks, specialized documents, triggers, permissions and execution history. Agents can turn evidence into owned work and durable outputs: lists, tables, flowcharts, reports and task-aware agendas. MCP exposes the supported tools for reading evidence, managing tasks, creating artifacts and configuring automation. Cedar's app adds the agent library, workspace controls, interactive delegation and workflow buttons.

## Choose the right surface

An external MCP client can call its advertised tools, edit authorized documents and configuration, and let Cedar execute persisted rules. It cannot call Cedar-only `delegate`, `board`, `workflow`, `chat-context`, history or connected-MCP dispatch tools. The app's agent management routes are product controls, not an additional external `agent` family.

Interactive chat can propose mutations or hand work to child executors. Background agents run with their own instructions and grants; availability in chat does not establish availability in a background worker. Customer outbound sends and schedules require the explicit user-directed path described in [message scheduling](/channels/scheduling).

## Configure a useful agent

Start with the business outcome and where its result belongs. Choose an existing system agent or library template where it already owns that outcome. Read current account instructions, prepare its configuration and output destination, check its grants, test its actual execution, then wire the intended trigger. A saved agent, an enabled trigger, a successful run and a delivered result are separate states to verify.

The task inventory shows who owns the next step; output documents hold the working result; run history records execution; source references and metric samples support the report's claims. [Data visibility](/brain/visibility) explains the access and coverage of each layer.
