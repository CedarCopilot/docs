Cedar helps protect connected accounts from overload by automatically checking account health, enforcing action limits, and queueing scheduled messages. When a scheduled LinkedIn DM reaches Cedar's hourly or daily send limit, Cedar keeps it pending and defers delivery.

Based on significant internal and external research, Cedar uses action-specific rate limits and recommends activity levels by account stage. Cedar handles enforcement of its limits and scheduled-message deferral automatically. These protections reduce risk; they are **not a guarantee** against provider restrictions.

## Automatic account protection

| Protection | What Cedar handles |
| --- | --- |
| Per-account limits | Checks the connected seat's allowance before an action; every applicable window must permit it |
| Account health | Checks provider/account health before sending |
| Scheduled-message queues | Saves approved messages for future delivery and claims queued work before sending |
| Hourly or daily DM cap | Defers scheduled LinkedIn DMs and checks the limits again at the next attempt |
| Visibility and control | Keeps scheduled items available for inspection and cancellation in Cedar |

Immediate sends return a limit error when capped. Use scheduled sends for automatic queue handling. See [automatic queueing](/automation/queueing) for delivery timing and failure handling.

## Enforced action limits

These are per connected LinkedIn seat, from the current governor implementation. They are application ceilings, not recommended targets or guarantees about LinkedIn restrictions.

| Action | Cedar cap |
| --- | --- |
| Native search | 25 per day |
| Profile views | 64 per day |
| Connection invitations | 80 per week |
| Direct messages | 30 per hour **and** 100 per day |
| InMail | 20 per month |
| Reactions through the underlying service | 40 per day; no standalone reaction action in this MCP family |
| Recipient resolution for invites | Separate 80 per week lookup budget |
| Recipient resolution for DMs | Separate 30/hour and 100/day lookup budgets |
| Recipient resolution for InMail | Separate 20/month lookup budget |

Cached recipient IDs avoid a live lookup. A new recipient can require both a lookup and send allowance. Each applicable window must permit the action. Provider throttles and account health can block an action even below these numbers.

Buckets use the service runtime's local calendar boundaries; weeks start Monday. Do not promise a recipient-local or Pacific reset time. There is no MCP action here for raising these limits, and no unified 200-actions-per-day Cedar governor across action categories.

## Recommendations by account stage

Account history affects the appropriate operating level. Use the following researched starting points to choose a conservative schedule within Cedar's enforced limits. The current governor applies the action limits above; it does not yet select a different warm-up tier automatically.

### New or lightly connected accounts

| Stage | Recommended starting point |
| --- | --- |
| Before automation | Build at least 100 connections manually |
| Week 1 after connecting | 5 invitations per day |
| Week 2 | 10 invitations per day |
| Following weeks | Gradually move toward 15–20 invitations per day |
| Below 1,000 connections | Keep invitations at 20–25/day or lower after warm-up |

Use the more conservative schedule for fresh accounts and avoid overlapping automation on the same seat. These starting points are informed by the [account preparation guide](https://help.heyreach.io/en/articles/10415479-can-i-use-a-free-linkedin-account-with-heyreach), reviewed October 29, 2026.

### Broader campaign guidance

For accounts with established activity, the [campaign pacing research](https://www.heyreach.io/blog/linkedin-company-expansion-strategy) gives these additional reference ranges (reviewed October 29, 2026):

| Account stage or action | Suggested level |
| --- | --- |
| New/idle profiles, first 1–2 weeks | 10–15 invitations/day |
| Warming profiles, weeks 3–4 | 15–25 invitations/day |
| Established, healthy profiles | Up to 30–40 invitations/day |
| Initial message volume | 20–30 messages/day |
| Initial profile views | 30–50 views/day |
| Follow-up spacing | At least 5–7 days between touches |

The two articles address different starting conditions. Use the lower new-account schedule when account history is weak, and remain within Cedar's **80 invitations/week** even when a daily recommendation would imply a larger total.

## Practical Cedar pacing

For a conservative initial DM program, 20 messages across an eight-hour working day is roughly one every 24 minutes. That is an example scheduling policy, not an enforced Cedar interval. Maintain one shared per-seat plan across workflows, leave room for normal user activity, and stop when account health or provider feedback requires it.

Use `schedule-send` for approved messages at the chosen times. Cedar manages the durable queue, checks its limits before delivery, and defers scheduled DMs when its own hour/day cap is reached. Working hours, warm-up pacing and coordination with activity outside Cedar remain part of your chosen schedule. [Queue behavior](/automation/queueing).
