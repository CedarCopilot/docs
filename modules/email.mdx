Use the [drafting skill](/skills/drafting) to prepare a reply in the rep’s voice. Draft preparation and approved delivery use separate actions.

## Mail reads

`mail` provides `find`, `list-sent`, `search-live`, `read-thread`, and `fetch-attachments`. Distinguish Cedar's stored context from the connected mailbox's live results. Search providers and query syntax can differ; use the loaded skills and returned capability/error information.

`conversation-write sync-gmail-thread` brings a missing Gmail thread into an existing authorized deal. Ingesting a thread does not send a response. `email-tracking list/get` reads classified engagement evidence; it does not turn on tracking or send mail.

## Draft communications

`draft-comms` prepares email, Slack, or LinkedIn content and can show a saved email draft. Draft creation can return a proposal depending on the surface. Use a real saved provider draft ID when moving into a send operation; a temporary/proposed identifier is not sendable.

## Immediate email send

`send-email` exposes a three-step lifecycle:

1. Open the real saved draft and confirm the sender, recipients, subject, body and attachments. Obtain the user's explicit send decision for that message.
2. Call `prepare` with the saved `draftId`. Review the returned snapshot. It includes an approval hash and can include a signed review token.
3. For an authorized send, pass the same draft ID and the returned review token unchanged. The contract also supports the reviewed approval hash. If the draft or thread changes, prepare it again and review the new snapshot.

```json
{ "action": "prepare", "draftId": "saved_provider_draft_id" }
```

`status` reads the send journal for the same draft. Unknown or in-progress outcomes need reconciliation, not a newly created draft or blind resend. Cedar applies mailbox ownership checks and its duplicate-send lock. The tool requires `email:send` even for this family's review/status operations.

## Email in a sequence

An email step in a [person-specific sequence](/recipes/person-outreach-sequence) is a draft instruction. Saving the sequence or attaching it to a task does not send the email. Review the selected person, sender, subject and body when preparing delivery.

## Schedule email

`schedule-send` with `channel: "email"` requires a future timestamp, the saved provider draft, connection ID, subject, recipients, and matching body. The service checks that the saved draft agrees with the requested message. A scheduled send is real delivery authorization, not another kind of draft.

## Interpret engagement carefully

Likely-human opens/clicks and raw events are separate counts. Proxies, automated image loads, privacy services, forwarding, and sender views limit attribution. A tracked recipient address is intended-recipient information, not proof that this person read the email. Use engagement as one input to a review rather than proof of buying intent.
