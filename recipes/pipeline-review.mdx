---
title: "Turn a pipeline review into owned follow-ups"
description: "Select the deals to review, check the evidence, and follow agreed commitments through an internal meeting and Task View."
---

A useful pipeline review ends with someone accountable for each next step. Suppose a buyer is waiting for a security questionnaire and the AE agrees to send it Thursday. Preserve the buyer's request as evidence and the AE's promise as a task with an owner and date.

## Before the review

1. Open the appropriate pipeline view. Adjust its filters to select the deals for this meeting. If you can edit the view, **Save filters** retains your selection. **Restore saved filters** returns to the saved selection.
2. Open each deal and trace disputed claims back to the original email, meeting or field history. Keep an estimated close date labeled as an estimate until a source supports a commitment.
3. Check for open tasks on that deal. Reuse the existing questionnaire task if it already represents the follow-up. Record a new task only for a distinct commitment.

## When the meeting produces tasks

For automatic capture, the meeting needs to reach a configured Internal playbook whose producer sends follow-ups to the chosen Task View. An admin can configure this for a team that runs internal pipeline meetings. An ordinary meeting recording alone does not enable the workflow. If weekly prep has also been configured, use its **Pipeline review prep** output before the call.

An eligible producer can create new tasks, update existing ones, and reference unchanged work in one batch. Check the saved result for each commitment, including the owner, linked deal, due date and source. A conflicting update needs a fresh review of the current task. A task save and its Slack delivery have separate outcomes.

## After the review

Open the Task View. With **live** Slack delivery, a committed batch can appear as one parent message with individual task cards in its thread. A scheduled view instead groups items into its digest; a silent view keeps the work in Cedar. Open the appropriate task and confirm the owner and next action. Completing the task updates its state. Sending a prepared customer message requires its own review and delivery action.
