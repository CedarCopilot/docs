## Capabilities

[Calendar overview](/channels/calendar) · [Complete capabilities](/capabilities/calendar).

<Accordion title="Full tool behavior and constraints">

Work with the user's Google Calendar. ACTIONS: (1) list-events — fetch events in a time range, enriched with linked CRM conversation info. (2) get-availability — check busy periods across the user's calendars before proposing meeting times. (3) modify-event — CREATE, UPDATE, or DELETE a calendar event (pick via the operation param: "create" needs summary/startDateTime/endDateTime/attendees; "update" needs eventId + the fields to change; "delete" needs eventId). Pass &#96;recurrence&#96; (RFC 5545 RRULE strings) to send a repeating invite. Before rescheduling or editing an existing event, check &#96;canModifyForEveryone&#96; from list-events — when it is false the user does NOT own the event and cannot move it for the other guests; Before create, resolve intended guests to actual emails from conversation/contact context. If an email is missing, look it up first or ask the user; never call create with an empty attendee list. modify-event will refuse the change, and you must offer to ask the organizer or propose times instead. In the in-app chat, modify-event streams a proposal card for the user to approve. On every other surface (external MCP, bots, automations) it applies the change immediately (creating/updating/deleting the real event and notifying attendees) — the calling client is the approval layer. Each action takes its params in a same-named object (e.g. action: "modify-event" pairs with a modifyEvent: &#123;...&#125; object) — omit every params object except the one matching your chosen action.

</Accordion>

## Operations and scopes

| Action | Capability | Baseline scope |
| --- | --- | --- |
| `list-events` | Read calendar events in a time range with available CRM context and modification rights. | `crm:read` |
| `get-availability` | Check busy periods across the user's calendars. | `crm:read` |
| `modify-event` | Create, update or delete real calendar events; external MCP applies immediately and can notify attendees. | `crm:read` |

Path, account role, feature gates, target ownership, and billing permissions can impose additional requirements.

### listEvents

| Field | Type | Required | Details |
| --- | --- | --- | --- |
| `timeMin` | string | Yes | Start of time range in ISO 8601 format (e.g., 2026-03-01T00:00:00-07:00). Required — the beginning of the period to fetch events for. If no clear input is provided, use the FIRST DAY of the current year. |
| `timeMax` | string | Yes | End of time range in ISO 8601 format (e.g., 2026-03-01T23:59:59-07:00). Required — the end of the period to fetch events for. If no clear input is provided, use the LAST DAY of the current year. |

### modifyEvent

| Field | Type | Required | Details |
| --- | --- | --- | --- |
| `operation` | `create` · `update` · `delete` | Yes | Which calendar mutation to perform. "create" needs summary/startDateTime/endDateTime/attendees. "update" needs eventId plus any fields you want to change. "delete" needs only eventId. |
| `eventId` | string | No | The Google Calendar event ID to update or delete. Required for operation=update/delete. |
| `summary` | string | No | Meeting title. Required for create. For update, provide only to change it. Use format "CompanyName &lt;&gt; CompanyName" if companies are clear, or "FirstName &lt;&gt; FirstName" if not. |
| `description` | string | No | Meeting description. For create, defaults to empty. If there is an agreed next topic, provide 2-3 bullet points. |
| `startDateTime` | string | No | Start time in ISO 8601 format (e.g., 2024-03-15T10:00:00-07:00). Required for create. MUST be in the future. |
| `endDateTime` | string | No | End time in ISO 8601 format (e.g., 2024-03-15T11:00:00-07:00). Required for create. MUST be after startDateTime. |
| `attendees` | array of object | No | Meeting attendees. Required and non-empty for create. BEFORE calling create, resolve every intended guest's actual email from conversation/contact context. If emails are missing, read that context first or ask the user; do not call create with an empty list. CRITICAL: ONLY include attendees whose ACTUAL email addresses you extracted from the conversation (headers, signatures, previous messages). ABSOLUTELY FORBIDDEN: making up emails or using placeholder domains (@example.com, @domain.com). Better to have fewer real attendees than fake ones. |
| `location` | string | No | Meeting location. For create, defaults to "Online" for virtual meetings. |
| `wantsMeetLink` | boolean | No | Whether to create a video conference link. For create, defaults to true when omitted, so leave it out. Pass false ONLY if the user explicitly asked for no video link or said the meeting is in person with no call. If they asked for a link, keep it even when the meeting is at an office. Never pass false on your own judgement. |
| `conferenceType` | `hangoutsMeet` · `zoom` | No | Which conference &#96;wantsMeetLink&#96; creates: &#96;hangoutsMeet&#96; (Google Meet, the default) or &#96;zoom&#96;, which Cedar mints on the user's own Zoom account and attaches to the event. Only set &#96;zoom&#96; when the user asked for Zoom by name; a user who has not connected Zoom gets an event with no video link rather than a failure. |
| `recurrence` | array of string | No | RFC 5545 recurrence rules to make this a repeating event, e.g. &#91;"RRULE:FREQ=WEEKLY;BYDAY=MO;COUNT=10"&#93;. Omit for a one-time event. Common patterns: daily "RRULE:FREQ=DAILY", weekly "RRULE:FREQ=WEEKLY;BYDAY=MO,WE,FR", biweekly "RRULE:FREQ=WEEKLY;INTERVAL=2", monthly "RRULE:FREQ=MONTHLY". Add ";COUNT=n" to stop after n occurrences, or ";UNTIL=YYYYMMDD" to stop on a date — do not set both. For "update", this REPLACES the whole recurrence (reissue every rule you want kept, or pass an empty array to make the series a one-time event). Always affects the WHOLE series — the tool resolves eventId to its series master itself, even if you pass a single expanded instance id from list-events. Other fields on the same update (time, summary, etc.) still apply only to the instance you named, if that's what eventId is. |
