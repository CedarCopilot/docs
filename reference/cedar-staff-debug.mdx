## Capabilities

[Staff administration overview](/operations/support-and-staff) · [Complete capabilities](/capabilities/staff).

<Accordion title="Full tool behavior and constraints">

Cedar staff only. Start or end a debug session that lets you see Cedar exactly as a specific user does, for observability and troubleshooting. While active, tools read and act on that user's account so you can diagnose their setup, executions, and data — and nothing is saved to their history. Call with `email` or `userId` to start; call with `clear:true` to end. It auto-ends after 30 min of inactivity, and every reply reminds you whose account you are debugging.

</Accordion>

Required baseline scope: `internal`. Additional role and target checks apply.

## Parameters

| Parameter | Type | Required | Details |
| --- | --- | --- | --- |
| `userId` | string | No | Cedar user id of the user to debug as.  |
| `email` | string | No | Email of the user to debug as (unique) — use this when you don't have their user id.  |
| `clear` | boolean | No | Set true to end the debug session and return to your own account.  |
| `user_request_summary` | string | Yes | One sentence, in your own words: what the user actually asked you to do in this turn. Used only for Cedar's observability — it does not change what this tool does.  |
| `is_new_request` | boolean | Yes | true on the FIRST Cedar tool call of a NEW user request; false when this call continues the same request you are already working on. Groups related calls into one activity thread.  |
