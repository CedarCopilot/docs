## Capabilities

[Organization administration overview](/configuration/team) · [Complete capabilities](/capabilities/organization).

<Accordion title="Full tool behavior and constraints">

ORG-ADMIN ONLY. Push one field definition or CRM mapping out to many reps at once, instead of repeating config-write/connection-write once per rep. Call config-read list-fields with targetUserIds:"org", rollup:true first to see who's uniform/diverging/missing. ACTIONS: (1) propagate-field — copies an ORG AOP's custom field definition (type/options/description/governance) onto targeted reps' own AOPs. Reps missing the field get it created; reps already matching it are a no-op; reps whose copy DIVERGES are refused (with the diff) unless force:true, which instead proposes an approval-gated overwrite — one card per rep, never a blanket accept. (2) propagate-mapping — copies one CRM field mapping from a source connection onto each target's OWN connection for the same provider (never the source's connectionId). Pass sourceAopId to propagate a Lead/Partner mapping instead of the default Deal one — the object is resolved from that AOP's own bound object, never a raw object name. Same missing/uniform/diverging-needs-force semantics; a select/list-type target field gets real CRM-introspected option reconciliation, same as connection-write. For a single rep's field or mapping use config-write/connection-write instead.

</Accordion>

## Operations and scopes

| Action | Capability | Baseline scope |
| --- | --- | --- |
| `propagate-field` | Copy an organization field definition to selected reps; report differences and gate forced overwrites. | `playbook:write` |
| `propagate-mapping` | Copy a CRM mapping onto each target's own provider connection with option reconciliation. | `playbook:write` |

Path, account role, feature gates, target ownership, and billing permissions can impose additional requirements.

### propagateField

| Parameter | Type | Required | Details |
| --- | --- | --- | --- |
| `sourceAopId` | string | Yes | The ORG aop whose field definition is the source of truth.  |
| `fieldKey` | string | Yes | The custom field's stable map key on the org AOP.  |
| `targets` | string&#91;&#93; or "uniform_and_missing" or "org" | Yes | Explicit array of userIds — every one must already be linked to the same org AOP as sourceAopId, or it is refused individually (the rest still run). "uniform_and_missing" — every rep whose copy already matches the org default, plus every rep who never configured the field at all; a rep whose copy genuinely diverges is silently excluded, never attempted. "org" — every rep linked to this org AOP, uniform/diverging/missing alike.  |
| `force` | boolean | No | Without this, a target whose copy diverges from the org default is refused (its diff is returned, nothing is touched). With it, a diverging target is instead proposed as its own approval-gated write — one card per target, never a blanket accept for the batch. LIMIT: force:true may only be used when AT MOST ONE target in this call is diverging — if more than one is, the ENTIRE call is refused outright (nothing written, not even uniform/missing targets) with the full diverging list, because accepting one force-proposed card replays this whole call and would otherwise silently apply every other diverging target too. Call once per diverging target instead.  |

### propagateMapping

| Parameter | Type | Required | Details |
| --- | --- | --- | --- |
| `sourceConnectionId` | string | Yes | The connection whose mapping for crmFieldName is the source of truth.  |
| `crmFieldName` | string | Yes | Identifies WHICH mapping on the source connection to propagate.  |
| `sourceAopId` | string | No | The source connection owner's AOP whose bound CRM object (a Lead, a Partner record, ...) this mapping belongs to. The object itself is resolved server-side from that AOP's boundObjectApiName — never pass a raw object name. Omit for the standard Deal mapping.  |
| `targets` | string&#91;&#93; or "org" | Yes | Explicit array of userIds, or "org" for every member of your organization (excluding the source connection's own owner). Unlike propagate-field there is no "uniform_and_missing" shortcut — a mapping's "uniform" is judged by rule-shape, computed the same way for every target regardless.  |
| `force` | boolean | No | Without this, a target whose existing mapping for crmFieldName diverges from the source is refused (diff returned, nothing touched). With it, it is proposed as its own approval-gated write instead. LIMIT: force:true may only be used when AT MOST ONE target in this call is diverging — if more than one is, the ENTIRE call is refused outright (nothing written, not even uniform/missing targets) with the full diverging list, because accepting one force-proposed card replays this whole call and would otherwise silently apply every other diverging target too. Call once per diverging target instead.  |
