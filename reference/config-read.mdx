## Capabilities

[Configuration overview](/modules/configuration) · [Complete capabilities](/capabilities/configuration).

<Accordion title="Tool behavior and constraints">

For "why didn't X happen"/system-behavior questions, load-skill('cedar-configuration') first — these actions read raw config, they don't explain behavior. ACTIONS: (1) read-playbook — mode="list"/"load_full"/"load_sections" of an AOP's PLAYBOOK.md, by aopId or aopName. load_full/load_sections also return the org playbook as &#96;orgPlaybook&#96; (a user-level-only read can miss real trigger/subagent wiring). mode: "list" also gives the caller's own AOPs (name/id/hasPlaybook/isNoOp). (2) read-settings — CRM/Slack connections (incl. connectionId, needed by apply-change) + user settings. (3) list-fields — every field's definition, mapping, and options (custom + built-in). MUST load-skill('cedar-configuration', 'fields-and-values') first — it has the full rules this omits. (4) get-user-identity — trusted identity and organization admin status for personal/team scope. (5) list-org-members — the caller's own org directory (id/name/email/image), optionally filtered by &#96;search&#96;; use it for a teammate's userId instead of querying the user table. (6) find-bot-slack-channels — every Slack channel Cedar's bot can actually post to, optionally filtered by &#96;nameFilter&#96;. Use before authoring any new Slack delivery target, never a runtime lookup left in prose. Admin/owner sees every channel the bot is in; a regular member sees only ones they're also in. For personal alert destinations use notify.list-slack-channels. Pass only the matching params object, e.g. readPlaybook for read-playbook.

</Accordion>

## Operations and scopes

| Action | Capability | Baseline scope |
| --- | --- | --- |
| `read-playbook` | List AOPs or load full/selected playbook sections, including relevant organization content and edit targets. | `docs:read` |
| `read-settings` | Read selected account settings and connected-system configuration. | `crm:read` |
| `list-fields` | Inspect field definitions, mappings and options, with supported organization rollups. | `crm:read` |
| `list-org-members` | Find IDs and directory details for members of the caller's organization. | `crm:read` |
| `get-user-identity` | Read trusted caller identity, organization and administrator/read-only/acting-as status; no parameter object required. | `crm:read` |
| `find-bot-slack-channels` | Find channels Cedar's bot can actually post to, subject to membership and administrator visibility. | `crm:read` |

Path, account role, feature gates, target ownership, and billing permissions can impose additional requirements.

## Caller identity

Call `config-read` with `{ "action": "get-user-identity" }` before selecting a personal or team setup target. The optional response branch `userIdentity` contains `userId`, nullable `organizationId`, `name`, `email`, nullable `image`, `isOrganizationAdmin`, `isReadOnly`, `actingAs` and `authenticatedActorUserId`. Identity comes from the session; this operation does not accept a target-user override. Raw credential retrieval remains app-only and is excluded from the external input schema.

### readPlaybook

| Field | Type | Required | Details |
| --- | --- | --- | --- |
| `mode` | `list` · `load_full` · `load_sections` | Yes | "list" — discover the user's AOPs (name/id/hasPlaybook/isNoOp/selectionProcedure/customAssignmentInstruction/orgAssignmentInstruction/effectiveAssignmentInstruction), optionally filtered by aopName. "load_full" — read the full PLAYBOOK.md for one AOP, plus its org-level playbook (&#96;orgPlaybook&#96;) if one exists, plus an &#96;editMap&#96;: every referenced subagent/resource and each inline PLAYBOOK.md surface, tagged with &#96;source&#96; (user&#124;org) + &#96;writeTarget&#96;. To edit playbook behavior, write to a target's &#96;writeTarget&#96; — do NOT choose user-vs-org scope by hand. "load_sections" — read only the named sections of one AOP's playbook (and the same sections of its org-level playbook if one exists), plus the same &#96;editMap&#96; (requires &#96;sections&#96;). |
| `aopId` | string | No | Explicit AOP ID to target for load_full/load_sections. Omit to use the conversation currently in context, or resolve by aopName instead. |
| `aopName` | string | No | AOP name to target instead of aopId (e.g. "Deals"). For mode="list", filters the returned list (case-insensitive; no match returns an empty list, not an error). For load_full/load_sections, resolves to an aopId via list-aops (case-insensitive exact match, then substring) — if nothing matches, the call fails explicitly rather than silently falling back to the conversation in context. |
| `sections` | array of string | No | Required for mode="load_sections". Section header names (without the "## " prefix) to extract, e.g. &#91;"Stages", "Objection Handling"&#93;. Each is matched independently and the results are concatenated. |
| `targetUserId` | string | No | Org owner/admin only: read another org member's playbook (theirs, not yours) — pass their userId. When set, mode="list" returns THAT member's AOPs (use it to find their aopId), and load_full/load_sections read their playbook. Pass an explicit aopId/aopName alongside it; the conversation-in-context fallback is yours, not theirs. Omit to read your own. Rejected for non-admins or a target outside your org. |

### readSettings

| Field | Type | Required | Details |
| --- | --- | --- | --- |
| `targetUserId` | string | No | Org owner/admin only: target a same-org member. Omit for self; non-admins and cross-org targets are rejected. |
| `userId` | string | No | DEPRECATED alias for targetUserId. Same authorization gate; prefer targetUserId. |
| `sections` | array of `connections` · `user_settings` · `inboxes` · `task_groups` · `credentials` · `data_services` | No | Which sections to load. "data_services" returns provider defaults, policy origins, versions, watcher defaults and credential availability (never secrets). "connections" returns the connectionId required by apply-change's CRM/Slack change types — call this before apply-change whenever you need one and don't already have it. "user_settings" includes agentExecutionEnabled/pushDraftsToExternalClient for visibility, but neither is settable from any tool: they are not fields on any apply-change change type, and agentExecutionEnabled is read-only here. Report them; never try to change them. "inboxes" returns custom inbox tabs, layout, and shared inboxSortingInstructions (read before changing sorting preferences or managing inbox tabs). "task_groups" returns the task lanes (get group ids before a manage_task_group update/delete/reorder). "credentials" returns the stored credential entries this user can reach (own + org): name, scope, instructions and which FIELD NAMES are stored. Never values. |

### listFields

| Field | Type | Required | Details |
| --- | --- | --- | --- |
| `aopId` | string | Yes | A user AOP id. Always returns both this AOP's own fields and its linked org AOP's fields, if any. |
| `targetUserId` | string | No | Org owner/admin only: target a same-org member user AOP (scope=user). Omit for self; non-admins and cross-org targets are rejected. |
| `targetUserIds` | array of string or `org` | No | View MANY reps at once instead of just yourself — orthogonal to &#96;targetUserId&#96; above (that names ONE teammate to act as; this names a SET to view). Omit for your own fields only (unchanged default). An explicit array of userIds, or the literal "org" for every rep on this SAME AOP type — every user AOP linked to the same org AOP as &#96;aopId&#96;, not everyone in the organization. Naming anyone other than yourself requires org-admin authorization (aop_field:org) and is refused otherwise. |
| `rollup` | boolean | No | true summarizes across every targeted rep — uniform/diverging/missing per field key, vs. the org default — instead of returning each rep's raw field list. Defaults to false when exactly one rep is targeted (returns the same flat field list as omitting &#96;targetUserIds&#96; entirely), true when more than one is. Pass explicitly to override either default. |

### listOrgMembers

| Field | Type | Required | Details |
