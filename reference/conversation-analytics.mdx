### Reporting semantics

- This catalog covers EVENT and DEAL metrics, plus ONE taxonomy-ATOM metric: "judged_strength" (average strength across every list-field atom whose field_id matches a target family glob, grouped by rep/deal/month and windowed by date like any other metric here). What is still NOT here: per-criterion distributions, counting occurrences, or aggregating a non-strength payload key — those still need `run-sql`, which also gives readable rep names and arbitrary per-deal normalization this catalog never will. Start with the `taxonomy-fields` tool to learn which fields exist, then load-skill("run-sql") for anything "judged_strength" cannot express.
- Every row returns &#123; group, value, n, sampleIds &#125; — n is the sample size, sampleIds (capped at 50) point back to the atoms/events summarized.
- groupBy:"outcome" and metric "win_rate" both REQUIRE an agent-supplied outcome:&#123; won:&#91;...&#93;, lost:&#91;...&#93; &#125; status mapping.
- The filter is the SAME TimelineFilter cube used by the timeline reader; omit conversationIds to scope org-wide.
- response_time/followup_time/post_meeting_time/reply_rate/event_count/stage_funnel/time_between_stages already generalize to any AOP as-is — none hardcodes an Opportunity-specific stage/status literal; stage and status vocab are always caller-supplied or read off the AOP's own field definitions. "win_rate" generalizes the same way (see its own note). "aop_conversion" is the one genuinely new Lead-band metric — an AOP reassignment is not a status value on any single AOP's vocabulary.
- "deals_dropped"/"quiet_gap"/"gave_up_count" share one `target` convention: an optional positive number of days (the quiet-gap threshold), defaulting to 10 when omitted. "hygiene"'s `target` is unrelated — an optional comma-separated subset of its field keys (company, contact, deal_value, next_step), defaulting to all four.

Live CRM amounts require one explicit rep, a close-date window and reporting timezone. Their verified inventory and per-currency totals differ from Cedar's stored deal metrics. [Reporting workflow](/crm/metrics).
