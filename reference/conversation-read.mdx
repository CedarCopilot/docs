## Capabilities

[CRM conversations overview](/modules/crm) · [Complete capabilities](/capabilities/crm).

<Accordion title="Full tool behavior and constraints">

Read Cedar CRM records. For connected CRM deals use action 4. ACTIONS: (1) get — conversation by ID; brief timeline by default, write_to_file for full content, expandEventId for one event. Email entries show observed opens/clicks when available. (2) find — locate Cedar conversations via `filters` (field/operator/value, ANDed): standard columns, computed booleans, or custom fields as "wm_&lt;fieldKey&gt;"; add extraFields for more columns. Call load-skill("conversation") for the full field reference. (3) search-semantic — find relevant events by vector/full-text search. For a named call/email, get its eventId here or in the timeline, then use get with expandEventId for the full source. (4) search-external-crm-deals — search the connected EXTERNAL CRM for a deal by keyword (get providerId from config read-settings first). related-activity — retrieve shared custom events linked through the deal account or its contacts. DEAL-INTELLIGENCE (over extracted sub-event taxonomy atoms): (5) timeline — one time-ordered stream across events + both taxonomy planes for 1+ deals, filtered by fieldIds/kinds/stages/reps/scores/payload/time. (6) field-evolution — one field's series over time, grouped by deal. (7) value-as-of — a versioned field's value+scores at a stage/date/event. (8) describe-field — a field's plane/scores/vocab/payload keys (learn before filtering). (9) raw-content — resolve a deal's RAW verbatim events to a doc-sink buffer (stage-marked); read via read-document (#lines/#words) + search-documents (regex). (10) search — semantic search over the atoms (same cube); hits point back. Large results → the doc sink. (11) definitions — discover account/contact field or event definitions. Choose kind; page with after/limit, or read an exact key and version. Pass each action's params in a same-named object; omit the others.

</Accordion>

## Operations and scopes

| Action | Capability | Baseline scope |
| --- | --- | --- |
| `get` | Read an authorized conversation's supported details and context. | `crm:read` |
| `find` | Find Cedar conversations using the family’s supported filters. | `crm:read` |
| `search-semantic` | Search meaning across already-synced conversation evidence. | `crm:read` |
| `search-external-crm-deals` | Find deals in the connected external CRM, separately from Cedar conversations. | `crm:read` |
| `record-profile` | Read an account or contact by Cedar ID, including enrichment, fields and linked organization events. | `crm:read` |
| `related-activity` | Read shared custom events linked through the deal’s primary account or contacts. | `crm:read` |
| `timeline` | Read a time-ordered stream across events and extracted fields for selected deals. | `crm:read` |
| `field-evolution` | Inspect one field's change or occurrence series over time, grouped by deal. | `crm:read` |
| `value-as-of` | Read a versioned field's value and scores at the resolved historical cutoff. | `crm:read` |
| `describe-field` | Discover a field's plane, score support, vocabulary and observed payload values. | `crm:read` |
| `definitions` | List current account, contact or event definitions, or read an exact saved version. | `crm:read` |
| `raw-content` | Resolve full source transcripts, email and Slack evidence into a readable/searchable document buffer. | `crm:read` |
| `search` | Search extracted taxonomy evidence and retain source IDs for timeline and verbatim follow-up. | `crm:read` |

Path, account role, feature gates, target ownership, and billing permissions can impose additional requirements.

### find

| Field | Type | Required | Details |
| --- | --- | --- | --- |
| `filters` | array of object | No | Filter conditions, ANDed together. Filter ANY field: standard columns (name, status, priority, dealValue, nextStepDate, lastContactedAt, aopName, primaryCompanyName, ownerId, …), computed booleans (crmSynced, hasFutureCalendar), or custom fields as "wm_&lt;fieldKey&gt;" (the ids in &lt;available_columns&gt;). e.g. &#91;&#123;"field":"status","operator":"in","value":&#91;"pilot_planned"&#93;&#125;,&#123;"field":"crmSynced","operator":"eq","value":true&#125;&#93;. For a name/company text search use an "ilike" filter (e.g. &#123;"field":"primaryCompanyName","operator":"ilike","value":"%example%"&#125;). For the "ownerId" field pass the literal "self" to scope to the calling user (resolved server-side). SCOPE: results are ORG-WIDE by default — every conversation in the caller's organization, including other members'. When the user asks about THEIR OWN deals ("my pipeline", "deals I own"), you MUST add &#123;"field":"ownerId","operator":"eq","value":"self"&#125; or the answer will silently include other people's deals. Each result carries ownerName / isOwnedByCurrentUser. |
| `eventFilter` | object | No | Optional event filter — filter by event types (include/exclude) or by event count (e.g. conversations with more than 5 emails via count). |
| `orderBy` | object | No | Optional sorting. Defaults to lastContactedAt desc. |
| `limit` | number | No | Maximum number of results to return. Default 20, max 50. minimum: 1 maximum: 50 |
| `extraFields` | array of string | No | &#91;flexible_query mode&#93; Additional fields to include in each result beyond the defaults. Standard fields (camelCase columns from crmConversations): "nextSteps", "statusOverview", "important", "lastEmailAt", "lastUpdatedAt", "updatedAt", "conversationScope" — returned as top-level keys on each result. Custom fields: pass "wm_&lt;fieldKey&gt;" (the ids shown in &lt;available_columns&gt;) to get their current values, returned under each result's &#96;customFields&#96; object keyed by fieldKey. Unknown standard field names are silently ignored; list-type custom fields are not returned inline (they accumulate per-event). |

### record-profile

Supply `recordProfile.kind` (account or contact) and `recordProfile.id` (the organization’s Cedar record ID). This works before a deal exists. Read the effective profile and each reserved field’s source, the current scalar values, and up to five newest observations per list. Each observation includes its stored UUID (`id`), value and timestamp. Pass `recordProfile.after` from `next` to continue field keys. To continue one list, pass `history: {key, before}` using that field’s `earlierCursor`.

Add `activity: {}` to include ten organization events linked directly to the record. Repeat with `activity.before` set to the returned `activity.next` for another page. Deal-private and channel activity are outside this feed.

```json
{
  "action": "record-profile",
  "recordProfile": {"kind": "account", "id": "20000000-0000-4000-8000-000000000001", "activity": {}},
  "user_request_summary": "Read this account’s ABM tier and recent events",
  "is_new_request": true
}
```
