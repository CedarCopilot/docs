<Accordion title="Tool behavior and constraints">

Creating/changing a CRM deal or conversation? FIRST read the effective crm-updater path from the agent directory (document-read), or use injected &lt;crm_write_rules&gt;, before searching email. Fallback only: #subagents/crm-updater.md. Cedar conversation actions. Create alone makes no external CRM record: (1) create — create a Cedar conversation. (2) update-fields — metadata/working memory; linkCrmDeal links first so fields sync to it. People: upsert value=&#123;people:[&#123;id,...changes&#125;]&#125;. History: append complete new entries; update existing IDs with changed properties only. New people need all required properties (evidence=[] if no verified quote). Preserve IDs and unaffected entries; supplied arrays replace. Roles: one buying role except Economic buyer + Decision maker together, plus at most one relationship role. (3) create-event — log a meeting/call/text/custom event. (4) mutate — move/reassign/merge/rename/refresh conversations or clear working memory. (5) reassign-ownership — transfer to an org member, adding membership if needed. (6) link-external-crm-deal — link existing search-external-crm-deals result; update-fields syncs values. (7) sync-gmail-thread — import missing live Gmail by threadId/searchQuery into an existing deal for processing. (8) convert-hubspot-lead — create/reuse the linked Deal, qualify the Lead, and hand off using configured stages/AOP. Requires saved in-app approval and enabled writes. (9) handoff-crm-record — link an existing record to another AOP, preserving source history; no provider changes. Requires saved in-app approval. (10) create-opportunity — durably propose or create an external CRM opportunity with account-specific fields and associations. (11) log-email-activity — propose logging one email to its linked CRM deal. Pass only the matching params object (e.g. updateFields for update-fields).

</Accordion>

## CRM conversion and handoff

| Action | Required parameter object and fields | Baseline scope |
| --- | --- | --- |
| `convert-hubspot-lead` | `convertHubspotLead`: source `conversationId`, `targetDealAopId`, `dealName`, `dealPipelineId`, `dealStageId`, `qualifiedStageId` | `crm:read` |
| `handoff-crm-record` | `handoffCrmRecord`: source `conversationId`, `targetAopId`, existing `targetRecordId` | `crm:read` |

Conversion creates or reuses the linked Deal, qualifies the source Lead and hands off through the configured stages and playbook. It requires saved in-app approval and enabled CRM writes; never choose default pipeline or stage IDs. Record handoff links an existing record into the destination playbook and preserves source history without changing the provider record. It also requires saved in-app approval. Neither action's availability bypasses approval, account or ownership checks.

Inspect `proposed` and returned record/conversation IDs: a proposed operation is not evidence that conversion or handoff completed.
