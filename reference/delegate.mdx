## Capabilities

<Accordion title="Full tool behavior and constraints">

Creating/changing a CRM deal or conversation? FIRST read the effective crm-updater path from the agent directory (document-read), or use injected &lt;crm_write_rules&gt;, before searching email. Fallback only: #subagents/crm-updater.md. Delegate a self-contained task to a child execution. Two kinds:  ACTIONS: - subagent: hand off to a Cedar subagent. Pass subagent: &#123; type, task, ... &#125;.   - type="orchestrator" — Cedar-native WRITES only (drafts, field updates, tasks) across 1+ conversations. NOT for code/HTML/JSON artifacts or external systems (Google Drive/Docs, HubSpot, Salesforce, Slack API, curl) — use action: "code" for those.   - type="analyzer" — READ-ONLY research over Cedar conversation content (emails, meetings, notes) with citations. Cannot write or call external systems. - code: hand off to a short-lived Claude Code session with Bash / WebSearch / WebFetch / Read / Write / Edit / Glob / Grep. Pass code: &#123; task, ... &#125;. Use for ALL external API calls, code execution, file generation, and web research. Describe the business goal, not the implementation.  Each action takes its params in a same-named object — omit every params object except the one matching your chosen action.

</Accordion>

## Operations and scopes

| Action | Capability | Baseline scope |
| --- | --- | --- |
| `subagent` | Delegate Cedar-native work to an orchestrator or read-only evidence analysis to an analyzer. | `in-app` — unavailable externally |
| `code` | Delegate bounded code execution, external APIs, file generation or web research to the code executor. | `in-app` — unavailable externally |

Path, account role, feature gates, target ownership, and billing permissions can impose additional requirements.

### subagent

| Parameter | Type | Required | Details |
| --- | --- | --- | --- |
| `type` | "orchestrator" · "analyzer" | Yes | Type of subagent  |
| `agentId` | string | No | Optional aop_agents row ID. When provided, creates a tracked sub-execution row and attributes tool calls to that named pipeline agent.  |
| `task` | string | Yes | Detailed task description for subagent. For analyzer type, provide a general/high-level task description for what information you need and the analyzer subagent will handle it  |
| `conversationId` | string | No | Optional conversationId to associate reasoning with (enables per-row reasoning display in canvas). For analyzer type, this scopes the analysis to a specific conversation.  |
| `originalQuestion` | string | No | For analyzer type: The exact question the user asked, verbatim. Provides context for answer generation.  |
| `skillToLoad` | "drafting" · "knowledge-base" · "calendar" · "conversation" · "tasks" · "multi-conversation-operations" · "customer-support" · "external-systems" · "connected-systems" · "research" · "documents" · "tables" · "notifications" · "cedar-configuration" · "collateral" · "wiki-extraction" · "coaching" · "run-sql" · "field-query" · "deal-intelligence-analysis" · "analysis-decomposition" · "daily-agenda" · "aop-selection" · "domain-identification" · "event-summarization" · "conversation-action-management" · "conversation-inspection" | No | Optional skill to pre-load in subagent (includes both chat and execution skills). Not typically needed for analyzer type.  |
| `resourceToLoad` | string | No | Optional resource within skill to load (e.g., "bant", "saya" for coaching)  |
| `context` | object | No | Optional additional context  |
| `streamToMainChat` | boolean | No | Whether to stream answer chunks as raw text in the main chat (like the main agent talking). Set to false when spawning multiple subagents in parallel. If you are calling this tool more than once, ALWAYS set this to false. default: false |
| `isInternalResearch` | boolean | No | Set to true when spawning an analyzer subagent for internal research (e.g., as part of drafting). When true, the analysis results will NOT be surfaced to the user in the canvas review UI. default: false |

### code

| Parameter | Type | Required | Details |
| --- | --- | --- | --- |
| `task` | string | Yes | Natural language description of what to do. Be specific: include URLs, file paths, API endpoints, expected output format, etc. The executor has full Bash + filesystem access and can write scripts, call APIs, and search the web.  |
| `context_data` | string | No | Additional context to inject into the executor prompt — e.g. API tokens, JSON payloads, file contents, or any structured data the executor needs. Use this instead of embedding large strings in the task description.  |
| `allowed_tools` | string&#91;&#93; | No | Override the default allowed tool set. Defaults to &#91;"Bash", "WebSearch", "WebFetch", "Read", "Write", "Edit", "Glob", "Grep"&#93;. Restrict this if the task only needs a subset (e.g. &#91;"Bash"&#93; for pure shell work).  |
| `working_directory` | string | No | Working directory for the executor session. Defaults to /tmp. Use this to scope file operations to a specific project or scratch space.  |
| `drive_access` | "read" · "collateral-write" | No | Google Workspace access level for this run. Defaults to 'read' — the executor may list, read and export Drive files but cannot create or modify anything. Pass 'collateral-write' ONLY when the task is to author a new Google Doc, Sheet or Slides deck (e.g. collateral creation); it additionally allows create/copy/batchUpdate.
