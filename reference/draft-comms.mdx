## Capabilities

[Drafting overview](/channels/drafting) · [Complete capabilities](/capabilities/drafting).

<Accordion title="Full tool behavior and constraints">

Draft a communication for user review or send. ACTIONS: (1) draft-email — saves a REAL draft in the mail provider (Gmail/Outlook) via the provider API (unless propose: true, which only streams a preview card without persisting anything). Body MUST be composed HTML. To attach files, first call document-read(&#123;action: "list", path: "#kb"&#125;) to find available uploads, then pass the relevant type="upload" document IDs in attachments. Optionally tag with draftCategory: emailResponses, scheduledFollowups, postMeetingFollowups, preMeetingPrep, conversationRefresh, executeTaskNow. (2) draft-slack-message — DRAFT ONLY, presents the Slack message to the user for review before sending (optionally tagged with taskType: response, follow-up, reminder, post-meeting, pre-meeting, reactivation, manual, calendar, crm-opportunity, field-approval). There is NO Slack API concept of a draft: this is always an ephemeral preview plus a user task carrying the Slack send action — nothing is created on Slack's side until the user clicks "Send to Slack" on the task card. Do not describe this as a saved Slack draft: unlike email, no provider draft exists. Do NOT use draft-slack-message when you need to send a Slack message immediately or autonomously — use notify(&#123;action: "send"&#125;) instead for direct/immediate sends. (3) draft-linkedin-message — save a plain-text draft for an existing LinkedIn chat or a verified first-touch recipient on an existing task. Persists in Cedar for user review and NEVER sends. No CRM deal required. (4) show-draft — read-only: display an already-existing draft as a card instead of linking to Gmail; pass real draftIds. Each action takes its params in a same-named object (e.g. action: "draft-email" pairs with a draftEmail: &#123;...&#125; object) — omit every params object except the one matching your chosen action.

</Accordion>

## Operations and scopes

| Action | Capability | Baseline scope |
| --- | --- | --- |
| `draft-email` | Save a real HTML provider draft, or return only a preview when propose is enabled. | `email:draft` |
| `draft-slack-message` | Create a review preview and Cedar task; no Slack-side draft or send occurs. | `crm:read` |
| `draft-linkedin-message` | Save a plain-text Cedar draft for an existing LinkedIn chat without sending. | `linkedin:read` |
| `show-draft` | Display an already-existing draft using its real draft ID. | `email:read` |

Path, account role, feature gates, target ownership, and billing permissions can impose additional requirements.

### draftEmail

| Field | Type | Required | Details |
| --- | --- | --- | --- |
| `conversationId` | string | No | REQUIRED UNLESS we are outside of the context of an existing conversation - The conversation ID to draft for. When provided along with taskDescription, a task card will be shown to the user. Omit when drafting outside of a CRM conversation context. format: "uuid" |
| `to` | string | Yes | REQUIRED - Recipient email addresses (comma-separated). Extract from user request or conversation context (look for "From:" lines in emails for replies). minLength: 1 |
| `cc` | string | No | OPTIONAL - CC recipients (comma-separated). Preserve the thread's existing to/cc structure: if prior replies in the chain put certain people in CC, pass them here explicitly. The agent's explicit CC assignment takes priority over reply-all expansion. |
| `bcc` | string | No | OPTIONAL - BCC recipients (comma-separated). Extract from conversation context or user request if mentioned. |
| `subject` | string | Yes | Email subject line. Extract from conversation context (for replies) or generate based on user instructions. minLength: 1 |
| `body` | string | Yes | Email body content in HTML format (already composed and ready to save) minLength: 1 |
| `threadId` | any or string or null | No | Thread ID if there is an existing thread in your given context. IMPORTANT: Look for "Thread ID: &lt;id&gt;" lines in the conversation context - these indicate existing email threads. If you see thread IDs in the context, you MUST extract and use the most appropriate one (typically the most recent thread ID that matches the recipient/subject). Only omit this field if there are NO "Thread ID: &lt;id&gt;" entries anywhere in the conversation context. Do NOT create a new thread if thread IDs are present in the context. Do NOT insert random IDs. |
| `draftId` | any or string or null | No | OPTIONAL - Only provide this when REWRITING an existing draft. For NEW drafts, omit this parameter entirely or pass null/undefined. If omitted, a new draft will be created. |
| `rewriteDraftOnThreadId` | any or string or null | No | OPTIONAL - Set this ONLY when the user asked you to EDIT / REWRITE / REPLACE an existing draft. Pass the Thread ID of the draft to replace (the same "Thread ID: &lt;id&gt;" from the context). Cedar will update that thread's existing draft in place instead of creating a second one. Omit for brand-new drafts. |
| `taskNotes` | string | No | Concise source/request context explaining this new task, including an explicit promise or requested deliverable when known. Do not invent facts. maxLength: 4000 |
| `taskViews` | array of object | No | For a NEW task, copy current authorized Task View IDs/revisions and grounded non-source values. Omit for edits to an existing task; its values are preserved. maxItems: 20 |
| `taskDescription` | string | No | OPTIONAL - A concise, actionable task description for the user (e.g., "Follow up to discuss Q2 pricing", "Send meeting reschedule request"). Required when conversationId is provided, as it will be shown on the task card. Do NOT describe what you are doing (like "Draft email") - describe what the user is accomplishing by sending this draft. minLength: 1 |
| `taskId` | string | No | OPTIONAL - The id of an EXISTING user task this draft fulfils. Pass it whenever you are drafting in response to a task you looked up (e.g. the user said "do my Example Account follow-up" and you found that task): it saves the draft for real and attaches it to that task, so the task shows "Open draft" instead of still looking untouched. Omit when the draft does not fulfil an existing task — do NOT guess an id. format: "uuid" |
| `attachments` | array of string | No | OPTIONAL - Document IDs of uploaded files in the Brain to attach to this email draft. Call document-read(&#123;action: "list", path: "#kb"&#125;) first to find available uploads, then pass the relevant type="upload" IDs here. |
| `propose` | boolean | No | When true, streams a draft card for user review without saving to Gmail. When false, saves immediately. In chat mode always pass true — the user clicks Create Draft to persist. Headless surfaces always save immediately regardless of this flag. |
| `additionalLabelNames` | array of string | No | OPTIONAL - Gmail label names to apply to the draft thread (created if they do not exist). ONLY use this when the user explicitly requests a label be applied to drafted emails, or the playbook explicitly instructs it. Never add labels speculatively. |
| `draftCategory` | `emailResponses` · `scheduledFollowups` · `postMeetingFollowups` · `preMeetingPrep` · `conversationRefresh` · `executeTaskNow` | No | OPTIONAL - The semantic category of this draft. Pass when you know the purpose: emailResponses = replying to an inbound email, scheduledFollowups = a scheduled or proactive follow-up, postMeetingFollowups = follow-up after a meeting, preMeetingPrep = pre-meeting agenda or prep email. |
