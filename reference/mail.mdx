## Capabilities

[Email overview](/modules/email) · [Complete capabilities](/capabilities/email).

<Accordion title="Full tool behavior and constraints">

Mail operations. ACTIONS: (1) fetch-attachments — download and read email attachment content by Gmail message ID. Pass messageId (from "Message ID:" on the email) and optionally attachmentId to fetch one file. (2) list-sent — fetch emails the Cedar agent drafted that were actually sent, to compare drafted vs. sent bodies. Use maxSimilarity &lt; 0.7 to find emails the user rewrote significantly. Each result's messageId can be passed straight into fetch-attachments to pull its attachments (null for older rows). (3) find — query sent/received emails by STRUCTURED criteria: direction (inbound/outbound), has attachments, sender, subject/snippet substring, date range. Use this instead of semantic search when you need emails matching specific metadata — e.g. "sent emails with attachments", "emails from X last week". Returns messageId values you can pass straight into fetch-attachments. (4) search-live — search the user's LIVE Gmail mailbox by full Gmail query syntax (search.messages-style, e.g. "from:person@example.com newer_than:30d has:attachment"); returns thread ids + subject/from/snippet. Use this (not find/search-semantic) for mail that may never have synced, or when you need the freshest state. (5) read-thread — read a full email thread LIVE from the mailbox by threadId (from search-live), including per-message observed open/click counts, timestamps, tracking-enabled flags and full event history with observed IP addresses when available. NOTE: for semantic (meaning-based) search over ALREADY-SYNCED mail, use conversation.search-semantic with filters.eventType: "email"; search-live is a raw live-mailbox query instead. Each action takes its params in a same-named object (e.g. action: "fetch-attachments" pairs with a fetchAttachments: &#123;messageId&#125; object) — omit every params object except the one matching your chosen action.

</Accordion>

## Operations and scopes

| Action | Capability | Baseline scope |
| --- | --- | --- |
| `fetch-attachments` | Read attachment content by a real message ID, optionally selecting one attachment. | `email:read` |
| `list-sent` | Find Cedar-drafted emails that were actually sent and compare draft versus sent content. | `email:read` |
| `find` | Query synced email using structured sender, direction, attachment, text and date criteria. | `email:read` |
| `search-live` | Search the live Gmail mailbox using Gmail query syntax, including mail not yet synced. | `email:read` |
| `read-thread` | Read a complete live email thread with available observed tracking evidence. | `email:read` |

Path, account role, feature gates, target ownership, and billing permissions can impose additional requirements.

### fetchAttachments

| Field | Type | Required | Details |
| --- | --- | --- | --- |
| `messageId` | string | Yes | Gmail message ID from fetch-conversation output (shown as "Message ID:" on each email). Required to fetch attachments. minLength: 1 |
| `attachmentId` | string | No | Optional attachment ID from the attachments list. When omitted, fetches and extracts text from all attachments on the message. |
| `write_to_file` | boolean | No | When true, writes large extracted content to a TASK_BUFFER doc instead of returning inline. |

### listSent

| Field | Type | Required | Details |
| --- | --- | --- | --- |
| `targetUserId` | string | No | Read the original and sent text of Cedar-drafted emails for this user. Same-org owners and admins may read a teammate’s draft analytics. Omit for your own emails. |
| `userId` | string | No | DEPRECATED alias for targetUserId, kept so existing callers keep working. It is NOT the authenticated identity: it names whose sent email to read, and goes through the same authorization gate. |
| `limit` | integer | No | Max emails to return. default: 15 minimum: 1 maximum: 50 |
| `maxSimilarity` | number | No | Filter to emails where the user changed the draft significantly. 0.6 = user rewrote &gt;40% of the content. Use this to find examples of what the agent gets wrong. minimum: 0 maximum: 1 |

### find

| Field | Type | Required | Details |
| --- | --- | --- | --- |
| `direction` | `inbound` · `outbound` | No | Filter by direction. Use "outbound" for emails the user sent. |
| `hasAttachments` | boolean | No | When true, only return emails that have file attachments. |
| `fromEmail` | string | No | Filter by sender email address (exact match). |
| `subjectContains` | string | No | Filter emails whose subject contains this string (case-insensitive). |
| `snippetContains` | string | No | Filter emails whose body snippet contains this string (case-insensitive). Useful for finding emails that mention a specific attachment by name, e.g. "explainer deck", "pitch deck", "qsbs-stacking". |
| `dateFrom` | string | No | ISO 8601 date — only include emails on or after this date. |
| `dateTo` | string | No | ISO 8601 date — only include emails on or before this date. |
| `limit` | number | No | Maximum number of results to return. default: 20 minimum: 1 maximum: 50 |

### searchLive

| Field | Type | Required | Details |
| --- | --- | --- | --- |
| `query` | string | Yes | Gmail search query — full Gmail search syntax (e.g. "from:person@example.com newer_than:30d has:attachment subject:intro"). Searches the user's LIVE mailbox, not Cedar's synced store. Returns thread ids + subject/from/snippet previews. minLength: 1 |
| `maxResults` | integer | No | Max threads to return. Default 10. minimum: 1 maximum: 25 |
| `folder` | string | No | Gmail folder to scope the search to. Default "inbox". |

### readThread

| Field | Type | Required | Details |
| --- | --- | --- | --- |
| `threadId` | string | Yes | Gmail thread id (from search-live-emails). Read LIVE from the mailbox. minLength: 1 |
| `connectionId` | string | No | Explicit mailbox connection ID; must belong to the executing user. |
| `includeTrackingHistory` | boolean | No | Include detailed open/click event history only when asked about tracking. Default false. |
| `messageId` | string | No | Read only this message, including an older message outside the newest page. |
| `offset` | integer | No | Number of newest messages already read. Default 0. minimum: 0 |
| `limit` | integer | No | Messages per page, newest page first and chronological within each page. Default 20. minimum: 1 maximum: 20 |
