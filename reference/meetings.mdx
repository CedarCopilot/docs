## Capabilities

[Meetings overview](/modules/tasks-calendar) · [Complete capabilities](/capabilities/meetings).

<Accordion title="Full tool behavior and constraints">

Meeting operations. ACTIONS: (1) find — locate meetings Cedar has already synced, by title, attendee (email / domain / name), organizer, date range, or a pasted meeting/recording LINK. Works identically for every provider because it reads Cedar's store, not the provider's API — none of which support title search. Use this FIRST whenever the user references a call ("the pricing discussion", "the call with Jane last week") or pastes a Fathom/Circleback link. (2) sync — pull a meeting that never reached Cedar from the connected recorder (Fathom, Circleback, Granola, Gong, …) and attach it to a deal. Providers only accept a days-back window, so narrow with titleContains / participant / url; 0 or 2+ matches syncs nothing and returns candidates to disambiguate with the user. (3) capabilities — what this user's recorder can actually do and how to search it well. Call before an expensive or possibly-impossible hunt (searching what was SAID, a wide date range, or after sync came back empty); not needed for ordinary lookups, since find and sync take the same parameters and return the same answers whichever recorder is connected. Each action takes its params in a same-named object — omit every params object except the one matching your chosen action.

</Accordion>

## Operations and scopes

| Action | Capability | Baseline scope |
| --- | --- | --- |
| `find` | Find synced meetings by title, people, dates, organizer or recording link. | `crm:read` |
| `sync` | Recover a missing recorder meeting and attach a single disambiguated match to a deal. | `crm:read` |
| `capabilities` | Inspect what the caller's recorder actually supports before a broad or specialized search. | `crm:read` |

Path, account role, feature gates, target ownership, and billing permissions can impose additional requirements.

### find

| Parameter | Type | Required | Details |
| --- | --- | --- | --- |
| `titleContains` | string | No | Match meetings whose title contains this string (case-insensitive).  |
| `participant` | string | No | Match meetings with this person among the attendees — an email, an email domain ("acme.com"), or a name. Matches the organizer too.  |
| `url` | string | No | Match by a meeting or recording link the user pasted — e.g. a Fathom call URL or a Circleback recording URL. Substring match against both meeting_url and recording_url, so the bare id from a pasted link works as well as the whole URL.  |
| `conversationId` | string | No | Only meetings already attached to this deal. format: "uuid" |
| `dateFrom` | string | No | ISO 8601 — meetings at or after this time.  |
| `dateTo` | string | No | ISO 8601 — meetings at or before this time.  |
| `hasTranscript` | boolean | No | When true, only meetings whose transcript actually made it into Cedar.  |
| `limit` | number | No | Maximum results. default: 20; minimum: 1; maximum: 50 |

### sync

| Parameter | Type | Required | Details |
| --- | --- | --- | --- |
| `conversationId` | string | No | The EXISTING Cedar deal to attach the meeting to. Defaults to the conversation currently in context — pass it explicitly when the user means a different deal. format: "uuid" |
| `externalId` | string | No | The provider's own meeting id, if you already have it from a previous call.  |
| `titleContains` | string | No | Narrow the provider window to meetings whose title contains this.  |
| `participant` | string | No | Narrow to meetings with this attendee — email, email domain, or name.  |
| `url` | string | No | Narrow by a pasted meeting/recording link (substring match).  |
| `organizer` | string | No | Narrow to meetings this person organized/hosted (email or name).  |
| `recordedBy` | string&#91;&#93; | No | Narrow to meetings recorded by these people. NOTE: who hit record, which is not the same as who attended — use `participant` for attendance.  |
| `teams` | string&#91;&#93; | No | The provider's own team grouping, where it has one. NOT APPLIED by any recorder today — passing it makes this tool return candidates to confirm instead of attaching.  |
| `meetingType` | string | No | The provider's own meeting-type taxonomy, where it has one. NOT APPLIED by any recorder today — passing it makes this tool return candidates to confirm instead of attaching. Prefer `titleContains` if the type is in the title.  |
| `daysBack` | integer | No | How far back to ask the provider for. This is the ONLY window most providers accept, so keep it as tight as the user's description allows. default: 30; minimum: 1; maximum: 365 |
| `providerId` | string | No | Force a specific provider. Omit to use the user's connected one.  |

### capabilities

| Parameter | Type | Required | Details |
| --- | --- | --- | --- |
| `providerId` | string | No | Ask about a specific recorder. Omit to describe the user's own connected one.  |
