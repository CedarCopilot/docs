## Capabilities

[Slack overview](/slack/overview) · [Complete capabilities](/capabilities/slack).

<Accordion title="Full tool behavior and constraints">

Read the connected user's LIVE Slack (not Cedar's synced store). ACTIONS: (1) search-live — search Slack messages by text (search.messages); returns matches (channelId + ts/threadTs + permalink + snippet) to inspect or pass to slack-write's sync-thread. (2) read-thread — read a specific thread (conversations.replies) or a channel's recent messages; if that channel is ALREADY linked to one of your deals the messages are also stored on that deal's timeline automatically (idempotent, returned as syncedTo + ingested), so no follow-up sync-thread call is needed; each message lists its uploaded files (id, name, type). (3) read-file: external MCP clients only: look at the image(s) on one message (channelId + messageTs &#91;+ threadTs&#93; from read-thread, optionally one fileId); images come back as image content. Inside Cedar's own chat it returns the file list only. search-live and read-file never persist, and an UNLINKED channel is never attributed on its own: use slack-write's sync-thread to pick a deal for one. Requires the Slack "search:read" grant; a user who connected Slack before it existed gets a reconnect-required error. Each action takes its params in a same-named object (action: "search-live" pairs with searchLive: &#123;...&#125;) — omit every params object except the one matching your chosen action.

</Accordion>

## Operations and scopes

| Action | Capability | Baseline scope |
| --- | --- | --- |
| `search-live` | Search the connected Slack workspace for current matching content. | `slack:read` |
| `read-thread` | Read a full Slack thread and supported context; linked-deal content may also be persisted. | `slack:read` |
| `read-file` | Read a supported Slack file through the caller's authorized connection. | `slack:read` |

Path, account role, feature gates, target ownership, and billing permissions can impose additional requirements.

### searchLive

Search the connected user's LIVE Slack for messages by text (search.messages). Returns matches (channelId + ts/threadTs + permalink + snippet) to inspect or to pass to slack-write's sync-thread. Requires the Slack "search:read" grant; if the user connected Slack before that scope existed, this returns a reconnect-required error.

| Parameter | Type | Required | Details |
| --- | --- | --- | --- |
| `query` | string | Yes | Slack search text — supports Slack search operators (e.g. "in:#deals from:@jane roadmap", "has:link renewal"). Searches messages the connected user can see. minLength: 1; maxLength: 500 |
| `count` | number | No | Max matches to return. Default 20, max 50. minimum: 1; maximum: 50 |

### readThread

Read a specific Slack thread (conversations.replies) or the channel's recent messages LIVE. If the channel is ALREADY linked to one of your deals, the messages read are also stored on that deal's timeline automatically (idempotent) and the response returns `syncedTo` + `ingested`. Otherwise nothing is persisted — use slack-write's sync-thread to choose a deal.

| Parameter | Type | Required | Details |
| --- | --- | --- | --- |
| `channelId` | string | Yes | Slack channel id (e.g. "C0123ABC") — from a search-live match. minLength: 1 |
| `threadTs` | string | No | Thread root ts (e.g. "1700000000.123456"). Omit to read the channel's most recent messages instead of a single thread.  |
| `limit` | number | No | Max messages to return. Default 100. minimum: 1; maximum: 100 |

### readFile

Look at the image(s) on one Slack message, LIVE. Images come back as image content (PNG, JPEG, GIF, WebP up to 3.5MB, at most 3 per call and 5MB in total). External MCP clients only: Cedar's own chat gets the file list, not pixels.

| Parameter | Type | Required | Details |
| --- | --- | --- | --- |
| `channelId` | string | Yes | Slack channel id, from read-thread or a search-live match. minLength: 1 |
| `messageTs` | string | Yes | The ts of the message that carries the file (`messages&#91;&#93;.ts`). minLength: 1 |
| `threadTs` | string | No | Thread root ts when the message is a reply in a thread; omit for a top-level message.  |
| `fileId` | string | No | One file id from `messages&#91;&#93;.files&#91;&#93;.id`. Omit to read every image on the message.  |
