## Capabilities

[Workspace preferences overview](/workspace/preferences) · [Complete capabilities](/capabilities/workspace).

<Accordion title="Full tool behavior and constraints">

Change the user's own settings and workspace layout. Call config-read read-settings first to get the current ids — every update/delete/reorder needs them. CHANGES: (1) update_user_settings — Slack notification preferences and mail settings (signatureEnabled, signatureContent, defaultEmailAlias, undoSendEnabled); read-settings sections:&#91;"user_settings"&#93; first. (2) update_inbox_settings — inbox layout (inboxLayout, importantSignal, inboxOrder) and shared Gmail/LinkedIn/Slack inboxSortingInstructions. Read sections:&#91;"inboxes"&#93; first; empty instructions clear. Sorting works before CRM admission and does not authorize sending. (3) manage_inbox — create/update/delete/reorder a custom inbox tab (split); read-settings sections:&#91;"inboxes"&#93; for inbox ids, accountId is resolved server-side. (4) manage_task_group — create/update/delete/reorder a task group (the lanes tasks are filed into); read-settings sections:&#91;"task_groups"&#93; for group ids. (5) update_webhook_export_config — set/clear the HTTPS endpoint Cedar POSTs conversation-field updates to on every change (url:null clears it). For CRM/connection config (field mappings, Slack sync, CRM sync toggles, connection instructions, playbook webhooks) use connection-write instead. For AOP custom fields and their CRM mappings use config-write. For playbook, subagent, and resource file edits use write-document.

</Accordion>

Required baseline scope: `playbook:write`. Additional role and target checks apply.
