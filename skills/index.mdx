Skills supply account-aware operating instructions; tools execute operations. Loading a skill does not add missing tools or bypass permissions. Use the named loader and resource exactly as listed.

| Skill | Loader | Capabilities |
| --- | --- | --- |
| [drafting](/skills/drafting) | `load-skill` | Draft or rewrite sales emails, Slack messages, and LinkedIn replies that sound genuinely human and conversational — follow-ups, meeting recaps, outreach, pre-meeting agendas, post-demo summaries, or any prospect/client communication, over email, Slack, or LinkedIn. Use when the user asks to draft, write, rewrite, or improve any email, Slack, or LinkedIn message. Ensures drafts match the user's authentic voice using their AOP style guide and examples. Includes email, Slack, and LinkedIn guidance in one load. |
| [knowledge-base](/skills/knowledge-base) | `load-skill` | Access the user's Knowledge Base text entries, uploaded KB documents, and any connected external MCP knowledge bases (e.g. product docs, support docs). Use when you need specific reference information: links, product details, pricing, competitor info, or documentation. For creating/updating/deleting KB entries, use the cedar-configuration skill instead. |
| [calendar](/skills/calendar) | `load-skill` | View existing calendar events or propose new calendar events for meetings. Use when the user asks about their calendar (e.g., "what's on my calendar today?", "when is my meeting with Jon?") or when scheduling meetings, creating calendar invites, or proposing meeting times. |
| [conversation](/skills/conversation) | `load-skill` | Find/filter CRM conversations, update conversation fields, create new conversations, log events, and reassign ownership. Filtering: analyzes natural language requests, suggests filter configurations, and executes queries to find matching conversations — streams filter suggestions to the frontend for user approval. Load when the user says ''show me'', ''find'', ''filter'', or asks about deals by status, date, priority, or company — e.g. ''show stalled deals'', ''find my Acme conversation'', ''which deals are in negotiation''. Updating: extracts information from communications and updates CRM conversation fields with clean, digestible, high-confidence content that respects temporal context and AOP governance; also creates new deals/conversations, logs meetings/calls/events, and reassigns conversation ownership. For creating a new opportunity in the connected external CRM (not a new Cedar conversation), see this skill''s opportunity-creation resource. For finding and linking an EXISTING external-CRM deal to a conversation, see ''Two different things are called "CRM"'' below. Also covers pulling a message in from the user''s LIVE Gmail, Slack, or LinkedIn when they say it belongs to a deal but it isn''t on the timeline — ''there was an email for this conversation from X'', ''we discussed this in Slack'', ''that LinkedIn thread isn''t showing up here'' — finding it in the channel, disambiguating with the user, and attaching it to the conversation; see ''Pulling a missing message in from Gmail, Slack, or LinkedIn'' below. |
| [tasks](/skills/tasks) | `load-skill` | Everything task-related: creating, updating, and canceling personal and sales-conversation tasks; surfacing and ranking follow-ups for today (use when user asks "who do I need to follow up with?"). Covers dedup, due dates, batching, and pipeline hints. The automated morning run lives in the separate `daily-agenda` skill. |
| [multi-conversation-operations](/skills/multi-conversation-operations) | `load-skill` | Required before batch operations across 3+ conversations — drafting emails for many deals, updating fields in bulk, or any task that processes multiple conversations individually. Provides concurrency limits and correct patterns. |
| [customer-support](/skills/customer-support) | `load-skill` | Report a problem to the Cedar team when the user sends the reserved phrase "flag this" — a signal that something went wrong or was unexpected. Call send-user-feedback immediately with a full debug snapshot: the current working context conversation (id, name), a summary of the recent chat messages in this thread, what action was last taken or what the agent last said, and any relevant state. The goal is to give the Cedar team enough context to reproduce or understand the issue. |
| [external-systems](/skills/external-systems) | `load-skill` | Connect to and interact with external, non-Cedar systems. Three paths: MCP-connected integrations (Notion, outreach trackers, custom tools) via call-mcp-tool; Cedar-integrated providers (Google, Salesforce, HubSpot, Slack, Stripe); and credentials the user stored themselves (Xero, Microsoft Graph, an internal API). The last two both go through get-provider-credentials, then an HTTP caller (run-code-executor in the background, native Bash in chat). Load when the user wants to read from or write to any external system. |
| [connected-systems](/skills/connected-systems) | `load-skill` | Guidance for interacting with a user's external systems (HubSpot, Salesforce, Attio, Notion, custom tools, etc.) from a Claude session connected to Cedar. Load when the user asks you to read from or write to any system outside Cedar itself. Tells you which systems the user has connected in Cedar and what to do if you don't already have a working tool for the one they need. |
| [research](/skills/research) | `load-skill` | Read your LinkedIn network and post reactors; look up external information about people and companies — structured profiles (LinkedIn, headcount, funding) via configured enrichment providers (Crustdata by default for rich research), real-time web/news search, and full page content fetching. |
| [documents](/skills/documents) | `load-skill` | Read, write, and search Cedar Docs — persistent agent memory for deal intelligence, research, working memory/task canvases, and meeting prep. Also load for complex multi-step tasks or when the user says "remember this". |
| [tables](/skills/tables) | `load-skill` | Build and drive a Cedar TABLE — a row-addressed spreadsheet an agent fills. Load before reading or writing ANY table document, and whenever a task has N independent units of work: designing the columns and their fill instructions with the user, binding columns to live Cedar data (`conversation.stage`, `conversation.fields.&lt;key&gt;`), sourcing rows from a query or an import, and fanning out one agent per row to fill them in parallel. |
| [notifications](/skills/notifications) | `load-skill` | Send notifications to the user via Slack DM, Slack channel, iMessage, or WhatsApp. Use when the automation needs to deliver a message or report. |
| [cedar-configuration](/skills/cedar-configuration) | `load-skill` | The foundational skill for anything related to CONFIGURING, DEBUGGING, or UNDERSTANDING Cedar — its data, or its outputs. Load it at the START of almost any task, before other skills or tools. Covers: how executions/runs work, integrations &amp; sync (why something did or didn't sync or happen), ownership and participant semantics, playbooks/AOPs and how their trigger blocks run, the Knowledge Base, company background, CRM field mappings and conversation fields, draft analytics, and where agent output (drafts, field updates, tasks, summaries) goes. It is Cedar's CONFIGURATION surface (the PLAYBOOK.md document is the primary control — read it to understand behavior, edit it to change behavior; playbook design/optimization, org vs. user split, IGNORE rules, full account design/redesign) AND its DATA-REPAIR surface (fixing a broken conversation, merging/moving/de-duplicating deals, reassigning AOPs, reproducing a missing draft or task). Use it for anything that requires understanding or changing how Cedar behaves or what it produced — and as baseline system context even when merely reading Cedar's data. |
| [collateral](/skills/collateral) | `load-skill` | Create any sales collateral — pitch decks, one-pagers, battle cards, case studies, ROI docs, executive briefs, competitive matrices, business cases, and mutual action plans. Use when the user asks to build, fill, or auto-generate any piece of sales or marketing content. Searches KB and Drive for existing examples to use as templates; builds from scratch with style exploration when none exist. Orchestrates format selection, content sourcing, style discovery, template building, and agent creation, supporting interactive design mode or direct execution. |
| [coaching](/skills/coaching) | `load-skill` | Sales methodology frameworks — BANT, SAYA (Sell As You Are), MEDDPICC, the rep onboarding coaching-report structure, and the per-stage sales process-doc template. Load when the AOP specifies a sales methodology (SAYA, BANT, MEDDPICC, etc.), when giving methodology-grounded deal feedback or call reviews, when building a rep onboarding coaching report, or when you need the authoritative structure for a per-stage sales process doc. |
| [run-sql](/skills/run-sql) | `load-skill` | Full column and join reference for the run-sql tool's CRM database tables. Load before writing any run-sql query beyond the simplest single-table lookup — the tool's own description only lists table/column names, not what each column means, its example values, or how tables join to each other. |
| [field-query](/skills/field-query) | `load-skill` | Discover, select, and query CRM field data (crm_conversation_field_values) for one or many conversations, then present results as a table when they warrant one. Covers competitor mentions, current provider/vendor, contract or renewal details, close/renewal dates or other deal timing, objections, pain points, and any other extracted or custom field — for a single deal ('did Acme mention X') or the whole pipeline ('which deals mentioned X', 'deals closing this week'). Load this BEFORE run-sql, conversation's find action, or conversation-read ever touch crm_conversation_field_values, even when the question also sounds like a plain listing/filter question or the right field seems obvious — filtering on a value still requires knowing which field_id holds it for this org, and a short question is not evidence the concept lives in only one field. |
| [deal-intelligence-analysis](/skills/deal-intelligence-analysis) | `load-brain-skills` | Analyze a customer's deals to uncover non-obvious, grounded sales insight from the extracted sub-event taxonomy — compare deals/reps, trace how a field (MEDDPICC, objections, next steps, discovery questions…) evolved, find what behaviors correlate with wins, and prove every claim against verbatim source. Load when the user asks *why* deals are won or lost, wants cross-deal patterns, rep coaching from real calls, objection / competitor / pricing analysis, cadence or timing analysis, or any question about what's actually happening across their pipeline that needs evidence, not vibes. Runs a hypothesis→proof loop over the Cedar MCP reasoning tools (conversation-read, conversation-analytics, document, run-sql); every number carries a sample size and drill-back, every qualitative claim carries a verbatim span. |
| [analysis-decomposition](/skills/analysis-decomposition) | `load-brain-skills` | Turn a high-level sales-coaching / diagnostic THEME (\"how are reps running discovery?\", \"how are we multithreading?\") into a personalized tree of sharp, grounded-but-creative sub-questions (lines of inquiry) that deal-intelligence-analysis can then chase over the extracted taxonomy. Use to PLAN an analysis for a specific org — informed by their actual seeded fields, their methodology, and prior conversations with them — before running it, or to build a proactive insight agenda. It is the front of the plan → analyze → critique pipeline. |

## Names present only in type declarations

`wiki-extraction` is present in the source name allowlist but absent from the executable skill registry. They are not advertised here as loadable modules. Use the runtime catalog rather than relying on a stale name.
